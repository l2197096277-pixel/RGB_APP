## 1. 角色与传输

```
┌────────────────────┐        BLE GATT         ┌────────────────────┐
│   Android 手机      │  ───────────────────▶  │  中科蓝讯灯控板     │
│   App = Central     │  ◀───────────────────  │  Peripheral         │
│   写入控制帧        │      Notify（可选）     │  执行、可选回报     │
└────────────────────┘                         └────────────────────┘
```

- 手机是 GATT Client / Central，负责扫描、连接、写 Control 特征值。
- 灯控板是 GATT Server / Peripheral，负责广播、执行指令。
- App 使用 Write With Response 串行发送。

## 2. GATT 定义

| 名称 | 16 位 UUID | Android 完整 UUID | 属性 | 说明 |
|---|---|---|---|---|
| Service | `0xBBB0` | `0000BBB0-0000-1000-8000-00805F9B34FB` | Primary Service | 灯控主服务 |
| Control | `0xBBB1` | `0000BBB1-0000-1000-8000-00805F9B34FB` | Write、Write Without Response | 手机写入控制帧 |
| Status | `0xBBB2` | `0000BBB2-0000-1000-8000-00805F9B34FB` | Notify | 预留状态/应答通道；当前 App 不依赖它 |
| Info | `0xBBB3` | `0000BBB3-0000-1000-8000-00805F9B34FB` | Read | 设备信息，可选 |
| CCCD | `0x2902` | `00002902-0000-1000-8000-00805F9B34FB` | Write | Status 的 Notify 开关 |

- 这是中科蓝讯属性表里的标准 16 位 UUID；Android 会自动展开成 `0000xxxx-0000-1000-8000-00805F9B34FB`。
- **广播 BBB0 不是连接前提**，但建议广播，App 会把设备标记成“幻彩灯”并优先排序。
- 设备名不要求固定；App 会扫描所有 BLE 设备，用户手动选择。

## 3. 帧格式

```
偏移   0     1     2     3 .. 2+LEN   3+LEN
     0x11  CMD   LEN   DATA...       CHECKSUM
```

| 字段 | 长度 | 说明 |
|---|---|---|
| Header | 1 | 固定 `0x11` |
| CMD | 1 | 命令字 |
| LEN | 1 | DATA 字节数，0–32 |
| DATA | LEN | 命令参数 |
| CHECKSUM | 1 | `(0x11 + CMD + LEN + DATA 所有字节) & 0xFF` |

### 校验和

协议表只写了“检验和”，没有写算法。这里定义为**累加和取低 8 位**：

```c
uint8_t checksum(const uint8_t *data, size_t len) {
    uint8_t sum = 0;
    for (size_t i = 0; i < len; i++) {
        sum = (uint8_t)(sum + data[i]);
    }
    return sum;
}
```

Java / Kotlin：

```java
static int checksum(byte[] data, int length) {
    int sum = 0;
    for (int i = 0; i < length; i++) {
        sum = (sum + (data[i] & 0xFF)) & 0xFF;
    }
    return sum;
}
```

> 如果中科蓝讯原厂固件要求 XOR 或其它校验方式，请告诉我，我可以只改校验函数，其它帧结构不变。

## 4. 协议表已定义命令

### 4.1 开关

| 命令 | 帧 | 说明 |
|---|---|---|
| 开灯 | `11 01 01 01 14` | DATA=01 |
| 关灯 | `11 01 01 00 13` | DATA=00 |

### 4.2 光效模式

每个模式是独立命令，DATA=`01` 表示启用该模式，`00` 表示关闭该模式。

| 模式 | CMD | 开启帧 | 关闭帧 | App 中的名字 |
|---|---|---|---|---|
| 跑马灯 | `0x02` | `11 02 01 01 15` | `11 02 01 00 14` | 流光跑马 |
| 呼吸 | `0x03` | `11 03 01 01 16` | `11 03 01 00 15` | 呼吸 |
| 火焰 | `0x04` | `11 04 01 01 17` | `11 04 01 00 16` | 火焰 |
| 律动 | `0x05` | `11 05 01 01 18` | `11 05 01 00 17` | 律动 |

短按模式：开启该模式（DATA=01）；再短按同一模式：关闭该模式（DATA=00），App 同时取消高亮。

### 4.3 灯光颜色

| 颜色 | DATA | 帧 |
|---|---|---|
| 红 | `01` | `11 08 01 01 1B` |
| 橙 | `02` | `11 08 01 02 1C` |
| 黄 | `03` | `11 08 01 03 1D` |
| 绿 | `04` | `11 08 01 04 1E` |
| 青 | `05` | `11 08 01 05 1F` |
| 蓝 | `06` | `11 08 01 06 20` |
| 紫 | `07` | `11 08 01 07 21` |
| 白 | `08` | `11 08 01 08 22` |
| 品红 | `09` | `11 08 01 09 23` |
| 关闭颜色 | `00` | `11 08 01 00 1A` |

App 会按这个顺序显示 9 个颜色圆点；再次点击当前颜色发送 DATA=00 关闭颜色并取消高亮。

### 4.4 亮度

| 命令 | 帧 | 范围 |
|---|---|---|
| 设置亮度 | `11 10 01 xx CS` | `xx=0x00–0x64`（0–100） |

示例：亮度 100% → `11 10 01 64 86`。

## 5. 补充命令

### 5.1 关闭光效模式

`0x06`，DATA=`01`/`00`：

- 关闭：`11 06 01 00 18`
- 恢复：`11 06 01 01 19`

App 的单个模式关闭使用对应模式命令 DATA=00；`0x06` 作为“关闭光效模式”的通用命令保留，供固件/调试使用。

### 5.2 一键关闭

`0x11 01 00`：

```
11 11 01 00 23
```

App 的“一键关闭”按钮发送这一帧，并同时把界面总开关置为关闭、所有高亮熄灭、亮度显示 0%。

### 5.3 自检

`0xFF`，DATA=`01`/`00`：

```
11 FF 01 01 12
```

### 5.4 亮灯数量

| CMD | 名称 | DATA | 说明 |
|---|---|---|---|
| `0x07` | 数量 +1/-1 | `01`/`00` | 加一颗：`11 07 01 01 1A`；减一颗：`11 07 01 00 19` |
| `0x09` | 直接设置数量 | `x` | `11 09 01 x CS`；x=0–255 |

直接设置示例：

```text
60 颗： 11 09 01 3C 57
255 颗：11 09 01 FF 1A
```

`0x07` 是**相对命令**，重复发送 3 次会加/减 3 颗，因此 App 每次点击只发 1 次，不做重复。

### 5.5 自定义单颗灯

`0x12`，按协议示例固定为：

```text
11 12 02 x y CS
```

- `x`：灯序号 0–255；
- `y`：1 点亮，0 关闭；
- 第三字节固定 `02`（LEN=2 字节：序号 + 状态）。

示例：

| 操作 | 帧 |
|---|---|
| 点亮第 3 颗 | `11 12 02 03 01 29` |
| 关闭第 3 颗 | `11 12 02 03 00 28` |
| 点亮第 10 颗 | `11 12 02 0A 01 30` |
| 关闭第 10 颗 | `11 12 02 0A 00 2F` |
| 退出自定义/全部关闭 | `11 12 02 00 00 25` |

App 为每颗灯维护高亮状态；快速点击时按点击顺序排队，一组 3 次发完再发下一组。

### 5.6 App 扩展命令

| CMD | 名称 | DATA | 说明 |
|---|---|---|---|
| `0x0A` | SPEED | `xx` | 速度 0–100；示例 60 → `11 0A 01 3C 58` |
| `0x0B` | QUERY | 无 | 查询当前状态；示例 `11 0B 00 1C` |
| `0x0F` | SYNC | 6 字节 | `[power, mode, color(0=关), brightness, speed, ledCount]` |

`SYNC` 示例（开灯、流光、青色、亮度 72、速度 60、60 颗灯）：

```
11 0F 06 01 01 05 48 3C 3C ED
```

如果中科蓝讯固件不需要这些扩展，可以忽略；App 的主要控制仍使用协议表已定义的 01/02/03/04/05/07/08/10/11/12/FF。

## 6. App 的发送节奏

用户每次操作，App 默认把**同一个命令连续发送 3 次，间隔 100ms**：

```
t=0ms   第 1 帧
t=100ms 第 2 帧
t=200ms 第 3 帧
```

例外：

- `0x07` 是相对命令，每次只发 1 次。
- 自定义 `0x12` 每组 3 次，串行排队；不会跳过。
- 亮度拖动时每约 120ms 发 1 次当前值；松手后再发 3 次。
- 模式切换先发旧模式关闭 3 次，延迟 600ms 再发新模式开启 3 次。

App 连接成功后会先发一次 `SYNC`（3 次）。

## 8. nRF Connect 联调

1. 扫描并连接你的产品（名称任意）。
2. 展开 `0000BBB0-...` 服务。
3. 找到 `0000BBB1-...`（Control），点写入。
4. 选择 **Write**（带响应），输入：
   ```
   11 01 01 01 14
   ```
   灯应开。
5. 输入 `11 08 01 01 1B` 切红色。
6. 输入 `11 03 01 01 16` 切呼吸。
7. App **不读取** `0000BBB2-...` 状态，也不写 CCCD；如设备有 Notify，可用 nRF Connect 自行开启观察原始字节。

## 9. 已知限制

- 协议表没有定义设备 → 手机的 ACK/状态帧，因此 App 采用“发送即认为成功”的乐观 UI。
- `Status` 已订阅，但当前只记录原始 Notify，不解析。
- 校验和算法是按“累加和”补充的；如果原厂固件用 XOR，需要同步改。
- 广播 BBB0、设备名都不是连接前提；真正必须的是 GATT 里的 BBB0/BBB1/BBB2。
