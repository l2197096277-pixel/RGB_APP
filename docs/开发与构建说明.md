# 开发与构建说明

版本：v1.1.1  
包名：`com.aurora.light`  
最低系统：Android 6.0（API 23）  
目标系统：Android 15（API 35）

---

## 1. 技术选型

| 项目 | 选择 | 原因 |
|---|---|---|
| 语言 | Java 8 | 无 Kotlin 运行时依赖，APK 小 |
| UI | 原生 Android View + 自绘 View | 不引入 AndroidX / Material，安装包约 236 KB |
| BLE | Android 原生 `BluetoothLeScanner` / `BluetoothGatt` | 直接、可控，无第三方 SDK |
| 构建 | Gradle 8.9 + Android Gradle Plugin 8.7.3 | Android Studio 可直接打开、调试、运行；`build.ps1` 保留为无 Gradle 备用方案 |
| 数据 | `SharedPreferences` | 只保存本机偏好，无数据库、无账号 |
| 网络 | 无 | 清单中未声明 `INTERNET` 权限 |

**没有**使用：Firebase、广告 SDK、统计 SDK、账号系统、云端接口、WebView。

## 3. 开发与构建

### 3.1 用 Android Studio 开发（推荐）

1. 安装 **Android Studio**（建议 Ladybug 2024.2 或更新版本，自带 JDK 17）。
2. 在 SDK Manager 安装 **Android 15 / API 35**。
3. `File → Open`，选择项目根目录 `aurora-light`。
4. 等待 Gradle Sync。首次会下载 Gradle 8.9、AGP 8.7.3 和 JUnit。
5. 手机开启 USB 调试并连接，点右上角 **Run ▶**；也可以先用演示模式看 UI。

Android Studio 会自动生成 `local.properties` 指向本机 SDK，不要提交到 Git。

> AGP 8 可能提示 `AndroidManifest.xml` 里的 `package` 属性已忽略；实际包名由 `app/build.gradle` 的 `namespace` / `applicationId` 决定。保留该属性是为了兼容无 Gradle 的 `build.ps1`，不影响构建。

**Debug 和 Release 都使用项目签名**（`keystore.properties` 指向 `keystore/aurora-release.jks`），所以：

- Android Studio 直接 Run 的 debug 包可以覆盖安装已发布的 APK；
- 改完代码不用卸载重装；
- 正式发包前只需要提升 `versionCode`。

### 3.2 命令行 Gradle

Windows：

```powershell
.\gradlew.bat test
.\gradlew.bat assembleDebug
.\gradlew.bat assembleRelease
```

macOS / Linux：

```bash
./gradlew test
./gradlew assembleDebug
./gradlew assembleRelease
```

产物：

```text
app/build/outputs/apk/debug/app-debug.apk
app/build/outputs/apk/release/app-release.apk
app/build/reports/tests/testDebugUnitTest/index.html
```

如果命令行没有设置 SDK，可先创建 `local.properties`：

```properties
sdk.dir=C\:\\你的路径\\Android\\Sdk
```

或设置环境变量 `ANDROID_HOME` / `ANDROID_SDK_ROOT`。

> 项目的 `gradle/wrapper/gradle-wrapper.properties` 使用腾讯镜像下载 Gradle 8.9，国内首次同步更快。如果镜像不可用，把 `distributionUrl` 改回：
> `https://services.gradle.org/distributions/gradle-8.9-bin.zip`。

### 3.3 版本号与签名

- 版本号在 [`app/build.gradle`](../app/build.gradle)：

```groovy
versionCode 7
versionName '1.1.1'
```

每次对外发版，把 `versionCode` 加 1，例如 `2`，`versionName` 改成 `1.1.1`。

- 签名配置在 [`keystore.properties`](../keystore.properties)：

```properties
storeFile=keystore/aurora-release.jks
storePassword=AuroraLight2026!
keyAlias=aurora
keyPassword=AuroraLight2026!
```

- 密钥别名：`aurora`
- 证书：RSA 2048，有效期 10000 天

**重要**：后续升级必须使用同一密钥。丢失密钥后，已安装用户只能卸载重装。正式发布前建议改成自己的强密码，并离线备份 JKS；不要把 `keystore.properties` 和 JKS 上传到公开仓库。

### 3.4 备用：无 Gradle 构建

适合没有 Android Studio、只想命令行出包的场景。依赖：

- JDK 17
- Android SDK：`platforms/android-35`、`build-tools/35.0.0`
- Python 3（仅用于把 `classes.dex` 写入 APK）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 `
  -Jdk "C:\Java\jdk-17" `
  -Sdk "C:\Android\Sdk" `
  -Python "C:\Python312\python.exe"
```

脚本会执行 `aapt2 compile/link → javac → d8 → 注入 dex → zipalign → apksigner`，输出 `dist/AuroraLight-v1.1.1.apk` 和 `dist/BUILD-INFO.txt`。

> Windows PowerShell 5.1 读取 UTF-8 中文脚本需要 BOM。仓库内的 `build.ps1` 已带 BOM；若重新保存后出现“字符串缺少终止符”，请保留 UTF-8 BOM。


或安装已签名的发布包：

### 3.6 用 VS Code 开发

VS Code 适合改代码、跑 Gradle 任务、安装和看日志；它**不是完整的 Android IDE**，断点调试 App 仍建议用 Android Studio。

1. VS Code 打开项目根目录。
2. 安装推荐扩展（打开项目时会提示）：
   - Java Extension Pack
   - Gradle for Java
3. `Ctrl+Shift+B` 构建 Debug。
4. `Terminal → Run Task`：
   - `Android: Build Debug`
   - `Android: Build Release`
   - `Android: Test`
   - `Android: Build + Install + Launch`
   - `Android: Logcat`
   - `Android: Clean`
5. 任务通过 [`tools/vscode-gradle.ps1`](../tools/vscode-gradle.ps1) 自动寻找 JDK/SDK，并调用 `gradlew.bat`。

配置文件：

- [`/.vscode/tasks.json`](../.vscode/tasks.json)
- [`/.vscode/extensions.json`](../.vscode/extensions.json)
- [`/.vscode/settings.json`](../.vscode/settings.json)

注意事项：

- 直接按 F5 不会启动 Android App；请用任务，或在 Android Studio 里 Run。
- 手机需要开启 USB 调试；`Build + Install + Launch` 会调用 `adb install -r` 和 `am start`。
- 如果自动探测失败，设置环境变量 `JAVA_HOME`（JDK 17）和 `ANDROID_HOME`（Android SDK 35）。
- 这套任务按 Windows PowerShell 编写；macOS/Linux 可直接在终端运行 `./gradlew ...`。

或把 APK 发到手机，用文件管理器点击安装（允许“安装未知应用”）。

## 4. 架构说明

### 4.1 状态流

```
用户操作
  │
  ├─ 更新 AuroraState（本地 UI 立即响应）
  ├─ saveState() 写入 SharedPreferences
  └─ 若已连接：AuroraProtocol 组帧 → sendBurst(3 次 / 100ms)
                          │
灯带 Notify ────────────────▶ 原始字节日志（当前协议未定义状态帧）
```

设计原则：**UI 先响应，蓝牙异步发送**。未连接时允许预先设置，连接成功后 `SYNC` 一次性对齐。

### 4.2 `AuroraBleManager`

- 扫描：`BluetoothLeScanner`，无过滤扫描 12 秒，按 RSSI/是否广播服务排序由 `ScanSheet` 完成。
- 连接：`connectGatt(..., TRANSPORT_LE)`。
- 服务发现：查找 3 个 UUID；缺失则报“该设备不是幻彩灯”。
- 订阅：写 Status 的 CCCD；1.2 秒兜底标记 ready（部分固件不回 `onDescriptorWrite`）。
- MTU：CCCD 写成功后请求 64。
- 写队列：`ArrayDeque<byte[]>` + `WRITE_TYPE_DEFAULT`，收到 `onCharacteristicWrite` 才发下一条；2 秒超时保护。
- 通知：订阅 `0xBBB2`，当前只把原始 Notify 字节写入日志；协议尚未定义设备→手机状态帧。
- 线程：BLE 回调在 Binder 线程，统一 `Handler(Looper.getMainLooper())` 切主线程。
- 生命周期：`close()` 停止扫描、断开 GATT、清空回调。

### 4.3 协议实现

所有 UUID 和命令集中在 `AuroraProtocol`。修改 UUID 时必须同步修改：

1. `AuroraProtocol.java` 的三个 UUID；
2. ESP32 固件中的三个 `*_UUID` 字符串；
3. 文档中的 UUID 表；
4. 若改了设备名前缀，同步 `DEVICE_PREFIX` 与固件 `snprintf`。

### 4.4 UI 实现

- `AuroraBackgroundView`：深色纵向渐变 + 4 团 `RadialGradient` 柔光 + 星点 + 底部渐暗；仅在可见时 30fps 刷新。
- `PowerButtonView`：径向光晕 + `SweepGradient` 扫光弧 + 玻璃圆盘 + 手绘电源符号；关闭后停止刷新。
- `ModeTileView`：用 `StateListDrawable` 与 `ColorStateList` 表达选中态。
- `ColorDotView`：选中有白色描边和外发光。
- `GradientTextView`：用 `LinearGradient` 给文字上色。
- 所有布局使用 `dp` / `sp`，适配 360dp 宽度；主内容可滚动。

## 5. 权限

| 权限 | 适用版本 | 用途 |
|---|---|---|
| `BLUETOOTH_SCAN` | Android 12+ | 扫描 BLE，声明 `neverForLocation` |
| `BLUETOOTH_CONNECT` | Android 12+ | 连接、读取设备名、GATT 操作 |
| `ACCESS_FINE_LOCATION` | Android 6–11（maxSdk=30） | 系统要求扫描 BLE 必须有定位权限 |
| `BLUETOOTH` / `BLUETOOTH_ADMIN` | Android 6–11（maxSdk=30） | 旧版蓝牙权限 |

- 未声明 `INTERNET`。
- 未声明后台定位、前台服务、通知权限。
- Android 11 及以下还必须打开系统定位开关；`ScanSheet` 会检测并引导。

## 7. 已知限制

- **未在真实灯带上做硬件在环测试**：协议和固件代码已按规范实现，但不同灯带/控制器需按协议适配后验证。
- 只支持单设备连接；没有多灯分组、场景保存、定时、音乐频谱（需要麦克风数据）功能。
- 没有自动重连（系统回收/超出范围后会断开，需要手动重连）。
- BLE 连接不加密、不配对；不适合安全场景。
- 没有 OTA 固件升级。
- 颜色为 RGB 直接映射，未做色温/亮度校准。
- 扫描列表会显示附近所有 BLE 设备，非本协议设备连接时会报错；这是为了方便调试。
- App 只发送 30/60/90 三档速度；协议支持 0–100。

## 8. 二次开发建议

### 8.1 日常修改流程

1. **先备份/建分支**：至少复制一份 `aurora-light` 目录，或使用 Git。
2. 用 Android Studio 打开项目，等 Gradle Sync 完成。
3. 改代码后先跑 `.\gradlew.bat test`（协议逻辑改动时必跑）。
4. 连接手机点 **Run ▶**；纯 UI 改动可先用演示模式看效果。
5. 涉及 BLE 的改动，用真实灯带或 ESP32 参考固件联调。
6. 发版前提升 `versionCode`，执行 `assembleRelease`，并把新 APK 和文档一起归档。

### 8.2 常见修改对照

| 想改什么 | App 侧 | 固件侧 | 备注 |
|---|---|---|---|
| 文字/颜色/图标 | `res/values`、`res/drawable`、`res/mipmap` | 不需要 | 改完直接 Run |
| 预设颜色 | `MainActivity.PRESET_COLORS` | 不需要 | RGB 范围不变 |
| 新光效 | `AuroraProtocol` + `MainActivity` | `applyCommand` + `renderLeds` | 协议模式表要同步更新 |
| 改 UUID/设备名 | `AuroraProtocol` | UUID/广播名 | 必须一起升级，旧固件不兼容 |
| 改亮度范围 | SeekBar/协议校验 | 亮度映射 | 当前统一 0–100 |
| 自动重连 | `AuroraBleManager` | 不需要 | 保存 MAC、断开后延时重连 |
| 多灯分组 | `AuroraBleManager` + 新页面 | 不需要 | 需要改单连接模型 |
| 登录/云同步 | 新增加网络层和后端 | 不需要 | 会引入 `INTERNET` 权限，破坏离线设计 |

### 8.3 具体建议

1. **改 App 名称/图标**：修改 `strings.xml` 的 `app_name`，替换 `res/mipmap-*` 图标，重新构建。
2. **改 UUID**：见 4.3；改完必须重新烧录固件。
3. **加新光效**：在 `AuroraProtocol` 增加 CMD / MODE 常量，`MainActivity` 加卡片，固件 `applyCommand` 与 `renderLeds` 增加分支。
4. **加自动重连**：保存上次 MAC，在 `onBleDisconnected` 后延时 `connectGatt`；注意退出页面时取消。
5. **加音乐律动**：手机端采集麦克风需要 `RECORD_AUDIO`，或灯带端接 MAX9814/INMP441，把包络映射到亮度；当前固件是模拟节拍。
6. **正式发布**：更换签名密钥、改 `versionCode`、补隐私政策、在真机多机型验证、考虑上架应用商店的合规要求。
